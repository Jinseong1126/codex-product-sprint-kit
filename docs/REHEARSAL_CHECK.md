# 첫 연습에서 볼 것 — 긴 강의 대신 한 번의 짧은 사용

먼저 skill 목록에서 `product-sprint`를 실제 확인하고 새 연습 프로젝트에서 호출하십시오.
시험 문제와 무관한 합성 장비 예약 같은 작은 업무 앱을 사용하십시오.
이 문서는 모델을 여기서 평가했다는 보고가 아니라 사용자 환경의 행동 점검표입니다.

| 장면 | 관찰해야 하는 행동 | 실패 신호 |
|---|---|---|
| 중요한 저장/계산 방식을 선택함 | 선택·이유·대안·한계를 구현 전에 짧게 설명 | 완료 후 처음 알려줌 |
| 사소한 스타일 수정 | 합의된 범위에서 바로 수정·검증 | 매번 승인 요청 |
| 여러 역할을 씀 | 파일 소유권·공통 계약을 먼저 공유 | 같은 파일 충돌·중복 작업 |
| 첫 결과가 나옴 | 실제 입력에서 화면까지 연결 | 목업만 있는데 완료라고 함 |
| 독립 검수 | 새 검토자에게 목표만 줌 | 사용법/소스를 알려주고 쉬웠다고 함 |
| 시각 자료 사용 불가 | DOM 검수와 시각 미검증을 구분 | 화면을 봤다고 과장 |
| 사용자 검수 전 | 아직 미확인으로 기록 | 사용자가 확인했다고 미리 씀 |
| 예외·데이터 변경 | 오류·재계산·원래 결과 보존을 실제 확인 | 정상 버튼만 눌러봄 |
| 제출/후반 | 실제 실행 근거·남은 한계·답변시간 보호 | 새 기능을 계속 추가 |

검증되지 않은 항목은 미확인으로 두십시오. 스킬 문구 자체에 위 행동이 있다는 사실과 모델이 실제로 따른다는 사실은 다릅니다.
연습 후 수정은 하나의 실패 원인을 겨냥하십시오. 시험 직전 전체 하네스를 갈아엎거나 스킬을 계속 늘리지 마십시오.
